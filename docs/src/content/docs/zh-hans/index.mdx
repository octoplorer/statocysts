## 一种通知模型，连接每个投递目标

<p class="home-lede">
  使用协议 URL 标识通知提供方，并行投递到多个目标，再通过统一 API 检查每一个失败结果。
</p>

<div class="home-feature-grid">
  <CardGrid>
    <Card title="使用 URL 寻址" icon="link">
      使用 <code>slack://…</code> 或 <code>email://…</code> 等通知目标选择提供方和接收者。
    </Card>
    <Card title="默认并行投递" icon="random">
      并发尝试所有已配置目标，不会在首次失败后停止。
    </Card>
    <Card title="检查每个失败目标" icon="error">
      通过一个 <code>NotificationDeliveryError</code> 获取所有投递失败的详细信息。
    </Card>
    <Card title="适配不同运行时" icon="window">
      根据需要使用 Node.js 入口，或排除仅服务端提供方的浏览器入口。
    </Card>
  </CardGrid>
</div>

## 从安装到完成投递

```ts title="notify.ts"
import { send } from 'statocysts'

await send(process.env.SLACK_TARGET!, {
  title: '部署完成',
  body: '生产环境运行正常。',
})
```

使用 `pnpm add statocysts` 完成安装，并将完整通知目标 URL 保存在环境变量或密钥存储中。
