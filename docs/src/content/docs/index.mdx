## One notification model. Every delivery target.

<p class="home-lede">
  Address providers with protocol URLs, fan out deliveries in parallel, and inspect every failed target through one consistent API.
</p>

<div class="home-feature-grid">
  <CardGrid>
    <Card title="Route by URL" icon="link">
      Select a provider and recipient with a target such as <code>slack://…</code> or <code>email://…</code>.
    </Card>
    <Card title="Deliver in parallel" icon="random">
      Attempt every configured target concurrently instead of stopping after the first failure.
    </Card>
    <Card title="Inspect every failure" icon="error">
      Handle one <code>NotificationDeliveryError</code> with details for each unsuccessful target.
    </Card>
    <Card title="Run where you need it" icon="window">
      Use the Node.js entry or a browser entry that excludes server-only providers.
    </Card>
  </CardGrid>
</div>

## From install to delivery

```ts title="notify.ts"
import { send } from 'statocysts'

await send(process.env.SLACK_TARGET!, {
  title: 'Deployment complete',
  body: 'Production is healthy.',
})
```

Install with `pnpm add statocysts`, then keep complete target URLs in environment variables or a secret store.
